# v0.7.3 — Complete VAI 3.5 benchmark with full mAP evaluation

## Headline

The KV260 + Vitis AI 3.5 benchmark now produces full classification (Top-1
+ Top-5) and detection (COCO + VOC mAP) results for 33 models. The numbers
reproduce the VAI 2.5 reference benchmark bit-for-bit on shared models,
demonstrating end-to-end methodological parity.

## Six decoder bugs identified and fixed

The first attempt at mAP evaluation produced ~0.0001 across all SSD/YOLO
models. Systematic diagnosis identified six independent bugs:

1. **Channel order** — `preprocess_for_model` was unconditionally swapping
   RGB→BGR. The 2.5 notebook respects each model's `cfg['ch']` declaration.
   SSD/YOLO models trained on RGB received reversed channels → mAP collapsed
   to ~0.
2. **SSD anchor count** — original generator produced 2268 anchors; model
   outputs 1917. `min()` truncation paired layer-1 model outputs with
   layer-0 anchors. Rewrote `ssd_mobilenet_anchors()` to implement TF
   Object Detection API's `reduce_boxes_in_lowest_layer=True` (3 anchors
   at layer 0, 6 elsewhere = 1917 total).
3. **SSD class_remap fallback** — old code used `c-1` for COCO ID gaps
   (12, 26, 29, …). 2.5 skips gap-class detections entirely. Switched to
   skip behavior for 2.5 parity.
4. **YOLO 3D-input check** — `decode_yolo` had an `if arr.ndim == 4:` guard
   but the eval loop passes 3D arrays. Decoder returned `[]` unconditionally.
   Fixed to handle both 4D and 3D.
5. **COCO/VOC bbox format** — GT was stored as XYWH but IoU expects XYXY.
   Decoder predictions were XYXY, GT was XYWH → IoU=0. Converted GT to
   XYXY in `load_coco_gt()` / `load_voc_gt()`.
6. **`evaluate_one_detection_model` early-return** — returned 1 value on
   xmodel-not-found, caller expected 2 → `ValueError: too many values to
   unpack`. Made the early-return signature consistent.

A seventh, cosmetic fix: `np.errstate` guard in `iou_xyxy` to silence the
divide-by-zero warning.

## Other notebook improvements

- **Top-5 accuracy now computed and recorded.** Previous version only wrote
  top-1; FIELDS list was also missing `accuracy_top5`, which caused
  `n_acc_images` to leak into the top-5 column for newly-added rows. Fixed
  both the eval logic and the schema.
- **Camera benchmark failure handling** (known issue): when the camera
  benchmark misfires on a row, partial garbage was written (`cam_fps=148`,
  `inf_ms=False`) rather than the row being marked failed. The 2 affected
  rows (inception_v4, ssdlite_mobilenet_v2_coco_tf) were manually cleaned
  for v0.7.3. Future work to make this automatic via try-except around
  the camera capture loop.

## Methodological findings worth highlighting in the thesis

1. **Prototxt-based preprocessing is non-optional.** AMD's per-model
   calibration parameters differ subtly from generic defaults (resnet50
   has `mean=[104, 107, 123]` not the standard `[104, 117, 123]`;
   inception_v4 uses `scale=1/128` not `1/127.5`). Hardcoded defaults
   drift by 10-20% on top-1 accuracy.

2. **VAI 3.5 stack reproduces VAI 2.5 results bit-perfectly.** Where the
   underlying model binary is the same, INT8 quantization on the same DPU
   IP produces identical inference outputs. Cross-runtime equivalence
   empirically confirmed on 5 SSD + 1 YOLO model.

3. **`resnet_v1_50_tf` and `resnet50_pt` produce byte-identical predictions**
   despite different framework origins (TF Slim vs PyTorch), suggesting
   quantization convergence at INT8 even when the FP32 weights differed.

4. **The 2.5 reference's 0.92 top-1 for inception_v4 (Caffe) was an
   artifact of data leakage.** The original 500-image sample came from a
   Kaggle ImageNet archive whose folders were training data, not validation.
   On a proper held-out set (ImageNetV2 matched-frequency), inception_v4
   (Caffe) measures 0.687 top-1 / 0.882 top-5 — a defensible
   thesis-quality number.

5. **3.5 outperforms 2.5 on yolov4_leaky_spp_m by ~2 mAP points** (0.6161
   vs 0.5967), consistent with the channel-order bug having degraded the
   2.5 result.

## Known issues remaining

- 5 catalogue entries in `_stage_benchmark.py` have name mismatches with
  AMD's bundle filenames and never downloaded (`mobilenetv2_pt`,
  `efficientnet_edgetpu-S/M/L_tf`, `mobilenet_edge_2_75_pt`). They appear
  in the report as smoke-test failures. Resolving requires checking each
  model.yaml in AMD's repo for the exact filename. Non-blocking for the
  thesis — these are minor models.
- Camera benchmark misfire handling: 2 rows had partial garbage. Fixed
  manually in the CSV; future work to make this automatic.
